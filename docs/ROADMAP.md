## Фаза 1. Спайк технических рисков ⬜ (самое важное, 1–2 недели)

Цель: на **реальных устройствах iOS и Android** проверить, что связка работает.

- ⬜ Сгенерировать нативный модуль: `npx create-expo-module@latest --local` → `modules/expo-midi`
  - iOS: CoreMIDI, приём `noteOn`/`noteOff`/`CC64` с `MIDITimeStamp`; BLE через `CABTMIDICentralViewController`
  - Android: `android.media.midi.MidiManager`, USB и BLE (`openBluetoothDevice`), разрешения BLE
  - Сравнить с готовыми библиотеками (например `@motiz88/react-native-midi`), если они живы, взять их
- ⬜ `notation-view`: Vite-бандл Verovio (WASM) → HTML-ассет → `react-native-webview`, загрузка MusicXML
- ⬜ Нажатие клавиши подсвечивает соответствующую ноту на стане
- ⬜ Замер: задержка «клавиша → подсветка» (цель < 50 мс по ощущениям, < 30 мс от нативной метки до JS), время рендера 4 тактов и всей партитуры на 10 страниц
- ⬜ Проверить способ получения `xml:id` и `staff` для каждой ноты (MEI vs toolkit API)
- ⬜ Dev build через EAS (`eas build --profile development`) на обе платформы

**Готово, когда:** на iPhone/iPad и Android-телефоне с цифровым пианино (USB и BLE) нажатая нота подсвечивается на стане без заметной задержки. Если нет — пересматриваем рендер (Skia/react-native-svg) или MIDI-слой **до** написания фич.

## Фаза 2. Импорт MusicXML и отображение нот (фичи 1 и 3) ⬜

- ⬜ `score-core`: распаковка MXL (fflate), парсинг MusicXML → `PracticeScore`, `validateMeasures()`
- ⬜ Тестовые фикстуры: аккорды, лиги, форшлаги, смена размера, два нотоносца, затакт
- ⬜ Импорт файла через `expo-document-picker` → копия в `documentDirectory`
- ⬜ Экран просмотра: целиком / по N тактам (1, 2, 4, 8), выбор рук (R / L / обе), листание свайпом
- ⬜ Тёмная тема для нот

**Готово, когда:** 5 разных реальных MusicXML из MuseScore открываются и листаются по фрагментам.

## Фаза 3. Библиотека (фича 2) ⬜

- ⬜ `expo-sqlite` + Drizzle, миграции, схема из ARCHITECTURE §5.2
- ⬜ Карточки: название, композитор, обложка (рендер первой системы или фото), прогресс
- ⬜ Переименование, удаление (мягкое), сортировка и фильтры: «недавно добавленные», «разучиваю», «давно не повторяла»
- ⬜ Разбиение на фрагменты при импорте (по N тактов, настраивается)

## Фаза 4. Режим игры через MIDI (фича 4) ⬜

- ⬜ `practice-engine`: `WaitMatcher` + тесты на фикстурах
- ⬜ Экран практики: подключение устройства, режим ожидания, подсветка, автоперелистывание
- ⬜ Экранная клавиатура для dev-сборки
- ⬜ `services/audio`: сэмплер пианино (сэмплы Salamander Grand, CC-BY), прослушивание фрагмента
- ⬜ Метроном на аудио-часах, темп 50–100 %, калибровка задержки
- ⬜ `practice-engine`: `TempoMatcher` (ритм), итог попытки: точность нот, ритм, пропуски, лишние

**Готово, когда:** фрагмент проходится в обоих режимах, результат попытки сохраняется в `attempts`.

## Фаза 5. Разучивание и повторение (фича 5) ⬜

- ⬜ Автомат статусов фрагмента + критерий освоения (ARCHITECTURE §5.3)
- ⬜ `Scheduler` (упрощённый SM-2), `review_schedule`
- ⬜ Статус произведения как агрегат, прогресс на карточке
- ⬜ Карта сложности по тактам (зелёный / жёлтый / красный)

## Фаза 6. Стрики и мини-уроки (фича 6) ⬜

- ⬜ `LessonBuilder`: повторы, у которых наступил срок + сложные + 1 новый, бюджет 5–10 минут
- ⬜ Экран урока с шагами, итог
- ⬜ Стрик по локальным датам (часовые пояса, смена дня в полночь), засчитывается за завершённый урок
- ⬜ Локальные напоминания (`expo-notifications`)

## Фаза 7. OMR: распознавание PDF и фото ⬜ (параллельно с фазами 3–6)

- ⬜ `infra`: Postgres, Redis, MinIO в docker-compose
- ⬜ `api`: модуль `omr` (jobs, presigned upload, статус), таблица `omr_jobs`, BullMQ-продюсер, анонимный device token + rate limit
- ⬜ Эталонный набор из 20–30 страниц фортепианных нот с готовым MusicXML (печатные PDF + фото телефоном); харнесс сравнения движков, метрики из ARCHITECTURE §7.2
- ⬜ Выбор движка по бенчмарку (кандидаты: Audiveris, oemer, homr)
- ⬜ `omr-worker`: PDF→PNG, предобработка, выбранный движок
- ⬜ `score-core`: проверка качества, `unscoredMeasures`, порог отказа (ARCHITECTURE §7.3)
- ⬜ Мобилка: загрузка, прогресс задачи, экран результата, кнопка «Здесь ошибка в нотах»
- ⬜ Деплой воркера (контейнер, CPU; GPU по необходимости)

**Готово, когда:** на чистых печатных PDF из эталонного набора < 10 % тактов исключено из оценки, а ошибочных тактов, которые проверка не поймала, < 2 %.

## Фаза 8. Бета ⬜

- ⬜ Sentry, аналитика ключевых шагов воронки (импорт → первая попытка → возврат на следующий день)
- ⬜ Онбординг: подключение пианино, калибровка, первое произведение (встроенный пример из public domain)
- ⬜ TestFlight / Google Play Internal testing
- ⬜ Юридическое: политика конфиденциальности, лицензии (Verovio LGPL, Audiveris AGPL, сэмплы)

## После MVP

Редактор распознанных нот (правка тапом, вырезка исходной картинки рядом с тактом), аккаунт и синхронизация (`auth`, `sync`), гибкая разбивка по фразам, автосоединение фрагментов, постепенное ускорение темпа, достижения, статистика, микрофон для акустического пианино, поиск нот, импорт по ссылке. Подробнее — в [IDEA.md](./IDEA.md).
